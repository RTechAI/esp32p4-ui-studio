# Hardware Example 05 — GPS / GNSS

Status: **PHYSICALLY PROVEN**.

## Hardware

- Waveshare ESP32-P4-WIFI6-Touch-LCD-7B
- u-blox NEO-8 GPS/GNSS module
- Dedicated 4-pin UART connector for module power and ground
- Bottom 12-pin GPIO header `IO3`
- Bottom 12-pin GPIO header `IO4`

## UART mapping

- NEO VCC → UART connector VCC / `Core_5V`
- NEO GND → UART connector GND
- GPS TX → bottom GPIO header `IO3` / GPIO3 → UART1 RX
- GPS RX ← bottom GPIO header `IO4` / GPIO4 ← UART1 TX
- 9600 baud, 8 data bits, no parity, 1 stop bit
- GPIO3 and GPIO4 are 3.3 V UART logic

Do not use GPIO38 / connector RXD as the GPS receive input. GPIO38 is shared
with the CH343P USB-UART TX output, and GPIO37 is shared with the CH343P
USB-UART RX input. There is no isolation on those nets. The bottom-header
GPIO3/GPIO4 pair is the physically proven ForgeUI Example 05 UART pair.

For the UART1 TX physical proof, firmware sends one read-only UBX-MON-VER poll
after the first checksum-valid NMEA sentence. The poll requests receiver version
information and does not change or save receiver configuration.

The UART data logic is 3.3 V. The UART connector VCC used by this proof is the
board `Core_5V` rail; module power acceptance does not make its UART pins 5 V logic.

## Proof criteria

`FG_GPS: UART RX alive` followed by `FG_GPS: NMEA alive` proves the first physical link. Checksum-valid NMEA reception can be established indoors without a satellite position fix. `FIX: NO FIX` is therefore not a UART or NMEA failure.

Physical certification observed a real GPS fix with 12 satellites, coordinates,
altitude, speed, UTC, HDOP and live Studio UI updates. The P4 also transmitted
UBX-MON-VER on GPIO4 and validated the response checksum. The receiver reported
`SW="ROM SPG 5.10 (7b202e)"` and `HW="000A0000"`.

Load the example in ForgeUI Studio and use the normal standalone export and manual Build & Flash workflow. The exported firmware includes the developer-owned Example 05 UART/parser implementation; Studio-generated UI code does not duplicate it.
